# Precision Instrument UI：精密仪器式信息界面

KATANAview 设计系统的根定义（2026-11-14 用户定，见 [decisions.md](../../../docs/decisions.md) 同日一条）。本页高于 README 的「原则」与其余各页；各页跟本页冲突时以本页为准，冲突处在本页 §9 列出并逐页改掉。

> 这不是一个装了很多图表的网站，而是一台经过精密设计、可以信赖的专业分析仪器。

它不是一种视觉风格，是一种**信息组织与交互秩序**。判断任何一个视觉元素只问一句：**它承担什么信息职责？** 答不上来的就去掉。

## 1. 定义：三个部分

| 部分 | 负责 | 主要落在 |
|---|---|---|
| **Engineering Documentation** 工程文档 | 信息结构、排版、标注、单位、可追溯 | 网格、标题层级、键值表、尺寸标注与编号引线、来源行 |
| **Scientific Instrumentation** 科学仪器 | 实时状态、测量、反馈、异常识别 | 状态灯、读数、阈值线、变化的编码、异常标记 |
| **Professional Trading Workspace** 专业交易工作区 | 工作流、空间记忆、快捷操作、高密度呈现 | 面板编号与分区、固定布局、联动、快捷键、表格密度 |

四种参考共同贡献这三部分，组合但不拼贴：

| 参考 | 取的是 | 不取 |
|---|---|---|
| 瑞士式网格与工程排版 | 严格对齐、清晰层级、精确标注 | 海报式大留白、为排版而排版 |
| Braun 工业设计 | 功能优先、减少装饰、控制视觉噪声 | 复古家电的外观 |
| 专业金融信息终端 | 高密度、快速定位、稳定的空间记忆 | 黑底满屏亮色字、靠颜色区分一切 |
| 航天工程技术文档 | 状态明确、单位精确、证据可追溯 | 档案感的做旧、打字机字体 |

## 2. 五条原则与它们的检查办法

每条都写成能检查的规则；「检查」一栏是门禁或审查里怎么证明做到了。

### 2.1 信息是主体

- 数据比容器重要。一个面板里**最多一层**容器边界（面板壳本身）；面板内部分区用留白与发丝线，不再套卡片。
- 边框、底色、阴影只用来表达**结构关系**（属于谁、哪层在上），不用来「好看」。
- 图表没有外边框以外的装饰；网格只在需要读数的轴向出现。
- 检查：组件审查时逐个元素问「它承担什么信息」；新件的文档页 `donts` 里写出删掉了什么。

### 2.2 精密的层级：五种信息各有固定语法

| 信息 | 语法 | 例 |
|---|---|---|
| **数值** | 等宽数字（`tabular-nums`）；右对齐，小数点对齐；千分位用窄空格；精度由品种或口径决定，同一列同一精度 | `73 920`、`1.99` |
| **单位** | 跟在数值后，小一档、次一级墨色，中间一个空格（ISO 80000）；单位只写一次（列头或数值后，不两处都写） | `131 / 150 %`、`0.15 ‰` |
| **时间** | ISO 次序（年-月-日 时:分:秒），等宽；区间用 `→`；时区不是本地时标出；相对时间（「2 分钟前」）只给状态，不给数据 | `2026-09-18 14:57:03`、`2024-01 → 2026-09` |
| **状态** | 灯 + 词，永不单靠颜色；词是固定词表（连接中 / 已连接 / 断开 / 受锁 / 估算 / 过期……），一个状态一个词 | `● 已连接`、`EST` |
| **来源** | 每个数字能回答「从哪来、什么时候」：面板页脚一行来源；估算值标 `EST`；模拟与回放常驻标识；研究账本不计入要写出 | `来源 / 本机回测 · akshare 日线 · 09-30 收盘` |

- 检查：数值组件只能用 `@katanaview/ui/quant/format` 的格式化（已有）；新增 lint：组件里出现数字文本却没走格式化与 `tabular-nums` 的，报错（要做，见 §10）。

### 2.3 密度可控

- 紧凑不是拥挤：节奏来自**行高、列宽、对齐、留白**四样，不来自缩小字号。
- 行高三档照旧（`row-tight` 24 / `row-base` 28 / `row-loose` 36），由面板声明。
- **克制不等于小字号**：数据字不小于 12px，汉字不小于 12px；层级靠字号档之间明确的差（标题与正文至少差一档、关键读数与标签至少差两档）、字重与墨色，而不是把一切压低。
- **克制不等于全灰**：语义色在它该出现的地方要足够明确（§2.5）；灰只给非语义的结构与次要信息。
- 检查：字号与行高只能取 token 档（已有 `k-text-*`）；文档站每页在 `dpr-1` 下断言数据字的计算字号 ≥ 12px。

### 2.4 动效有因

只有三类原因能产生动效，其余一律静止：

| 原因 | 反馈 |
|---|---|
| **数值变化** | 数字原地变（等宽，不跳位）；需要提示方向的地方给一次短暂底色（≤ 300ms），不闪烁、不循环 |
| **订单成交 / 状态切换** | 状态灯切换 + 对应行一次标记；交易类同时有声音（sound.md） |
| **用户操作的直接响应** | 按下、拖动、展开的物理反馈（motion.md 的弹簧） |

- 不做：装饰性的循环动画、加载以外的呼吸灯、入场表演、扫描线、闪烁的辉光。
- 检查：动效 token 只能在上面三类的处理函数里用；审查时对每个动效写出它的「因」。

### 2.5 颜色有语义：通道互不混用

| 语义 | 通道 | 不许拿来表达别的 |
|---|---|---|
| 涨 / 跌 | `pnl-up` / `pnl-down`，**只上数字与线**，不上面积 | 不表达买卖、好坏、状态 |
| 买 / 卖 | `side-buy` / `side-sell`（盘口、下单、成交方向） | 不跟涨跌共用色值（同一屏上两者同时出现时必须分得开） |
| 异常 | `signal-amber`（接近限额、数据过期）、`signal-red`（越限、断开、拒单），永远带词或图标 | 不表达跌 |
| 选中 / 焦点 | 唯一强调色 `accent`（实色填充或 2px 边） | 不表达状态、不表达涨 |
| 失效 / 不可用 | 降墨色（`ink-400`）+ 删除线或「失效」词；不另起颜色 | — |
| 联动组 | `link-a…d`：面板头的组号块与共享游标同色 | 不进图表序列 |
| 类别序列 | `series-1..7` 固定顺序；序数用 `seq-*`；正负量用 `div-*` | 不进状态与选中 |

- 检查：组件样式里不许出现原始色值，只能用语义 token（已有 `theming.test.ts` 方向，补一条 lint）；`side-*` 与 `pnl-*` 在默认主题里的 ΔE 要有下限（测量后定，开测量票）。

## 3. 精密文档不是静态文档：动态数据下的阅读秩序

实时终端最大的挑战是**让高度动态的数据保持稳定的阅读秩序**。

| 场景 | 规则 | 怎么证明 |
|---|---|---|
| 行情刷新 | 数值变，**列宽、对齐、整体布局不动**：等宽数字 + 按最大可能位数预留列宽 + 小数点对齐；不因位数变化换行或挤动邻列 | e2e：连续推 N 次更新，断言所有单元格 `getBoundingClientRect` 不变（布局偏移为 0） |
| 订单簿更新 | 分清三种变化：**数量变化**（量条长度过渡 + 一次方向底色）、**价格移动**（档位整体平移，不是逐格重写）、**档位消失**（淡出 + 不立即补位，下一帧再收拢） | 单测：给定前后两帧，变化分类函数返回 qty / shift / remove；e2e 读像素证明三种编码不同 |
| 热力图 | 先表达**流动性强弱**：单一色相明度阶（`seq-*`），对数映射；不用彩虹色、不用全饱和 | 单测：映射函数单调、对数；文档站断言色值取自 `seq-*` |
| 多面板联动 | 明确告诉用户哪些视图**共享同一个时间、品种或价格位置**：面板头显示联动组号块（`link-*`）；共享的十字线、时间游标、价位线在组内所有面板同时出现、同色同样式；不在组里的面板不出现 | e2e：在一个面板移动游标，同组面板出现游标、别组不出现 |
| 数据过期 / 断流 | 不清空、不画假数据：保留最后的值，降墨色并标「过期 · 时:分:秒」；恢复后去掉标记 | e2e：断开模拟源，断言标记出现、数值不变 |

## 4. 视觉语言的分配

| 层 | 约占 | 负责什么 | 落在哪 |
|---|---|---|---|
| **工程文档秩序** | ~65% | 网格、对齐、标题层级、键值表、单位、标注、来源 | 每一屏的骨架 |
| **工业设备语义** | ~25% | 设备的**身份、状态、操作语义**：面板编号与分区（`K-01`）、数据标签、状态灯、操作反馈、模块之间的关系 | 面板头、状态栏、联动、确认流程 |
| **品牌视觉个性** | ~10% | 一个强调色、一款标题字、少数签名时刻（开机、大屏） | 每屏至多一处 |

比例是方向，不是配额。可检查的是下面的预算：

- 每个面板：品牌元素至多 1 处；工业设备语义只出现在面板头、状态行与操作反馈里，不进数据区。
- 弐瓶勉的价值在**复杂系统的结构表达**：模块之间的关系、尺度层级、编号体系，用在工作区布局图、联动关系、运行中心的拓扑上；不用机械线条或科幻装饰。
- 明日方舟的价值在**工业设备的身份、状态和操作语义**：设备编号、状态牌、操作确认的仪式感；不用黄色警告条、不加装饰性文字。

## 5. 文档语法（从参照图里取的部分）

只取承担信息职责的部分：

- **页 / 面板编号**：`K-01`、`RUN/2C91`、`BLATT 01 / 03`——身份与位置，空间记忆的锚。
- **章节号用强调色写大号数字**（`01`、`02`）：只在报告与大屏，不在工作台面板里。
- **黑底标签条**：一个面板至多一条，写这块是什么（`回测 · 费率敏感性`）。
- **键值表**：标签次一级墨色、值主墨色，发丝线分隔，标签列等宽。
- **尺寸标注线与编号引线**：标出图上的关键量（`MDD −7.7 %`）与事件（`01 费率上调`），编号与下方表格或日志一一对应。
- **来源行**：面板或报告页脚。
- **套准标记、页角方点、色板条**：只在导出的报告与大屏，工作台面板里不放（它们在纸面上是信息，在工作台里是装饰）。

## 6. 组件的样子：参照图 + TradingView 的组件（2026-11-14 用户定）

- 用户：「按照参考图还有 TradingView 的组件去做」。**信息语法**照参照图（本页 §5）；**组件的形态**（控件尺寸、密度、交互形态）参照 TradingView 的组件。商业产品只读、量、记出处，不抄代码（AGENTS.md）。
- **配色不跟 TradingView**：用户同日定「我们之前配色都搞定了」——颜色一律用现有 token（Console / Graphite 两套深色主题与它们的信号色、涨跌色），强调色仍是现有的 `signal-orange`（各主题自己的值）；不引入 TradingView 的色值。
- 尺寸与密度（控件高、圆角、字号、行高）参照 TradingView 实测；没实测的沿用 OpenMarket 已有的实测值，测到后替换并记出处。

## 7. 两种主题，同一套语法

- **默认 Graphite**（2026-11-11 用户定「不要现在黄色」「石墨没问题」，PR #1776；2026-11-14 再确认）：中性色是纯灰，信号色是油画颜料色；Console 留着可切，但它的中性色偏暖发黄，不作默认。
- **浅色（Paper）**：现有的浅色主题，给研究与报告；不用暖白底配高明度黄。
- 不用：暖白底配高明度黄（2026-11-14 用户：「太伤眼睛」）；大面积高饱和色块；辉光、扫描线、做旧（用户：「过头了」「老旧的感觉」）。
