# 盘口三件：订单簿、深度图、成交明细

订单簿把买卖挂单排成阶梯：卖盘在上、买盘在下，中间一行是最新价与价差；用户切「买卖 / 只看买 / 只看卖」、切合并档位，看底部的买卖占比条，点一行把价与方向交给页面。深度图把同一份档位画成两侧累计量，鼠标或方向键读价格、累计量与距中间价。成交明细列最近的成交，主动买卖着不同色，可以把紧挨着的同价同向成交并成一行。

## Sub-features

- `book-sides` 买卖并列：卖盘 8 行在上、最远的在最上面，最优卖价贴着中间行；买盘 8 行在下，最优买价紧挨中间行；中间行写价差。
- `book-modes` 「只看买」「只看卖」：另一侧消失，这一侧变 16 行；「买卖」回到 8 + 8。
- `book-merge` 合并档位：选 0.5 以后每个价都是 0.5 的整数倍，卖价向上取整、买价向下取整；价差仍按原始档位算。
- `book-share` 占比条：买占比 = 屏上前 8 档买量 /（买 + 卖），一位小数，两个数加起来是 100；换模式数不变。累计列从最优价起逐行累加。
- `book-pick` 点一行：页面收到合并后的价与「买盘 / 卖盘」。
- `depth-read` 深度图：聚焦后 → / ← 一档一档读，Esc 清掉；鼠标放在左半边读买盘（距中间价为负），移开清掉。
- `tape-list` 成交明细：逐笔 18 行，新的在上，主动买与主动卖价格颜色不同。
- `tape-aggregate` 「聚合」：紧挨着的同价同向并成一行，右边写 `×n`。

## How to get to it (user POV)

- 文档站左侧目录「积木」一组：`OrderBook 订单簿`（`#/order-book`）、`DepthChart 深度图`（`#/depth-chart`）、`TradeTape 成交明细`（`#/trade-tape`）。
- 订单簿：预览区「订单簿 BTC-演示」面板里，`group「订单簿（演示）」`，上面两组切换 `显示模式`、`合并档位`；面板下面一行回显点价。
- 深度图：预览区「深度图 BTC-演示」面板，图是 `group「深度图（演示）」`，可聚焦；上方 `横轴范围` 切换。
- 成交明细：预览区「成交明细 BTC-演示」面板，上方 `聚合`（逐笔 / 聚合）与 `大单阈值` 两组切换。
- 三页都有「实时 / 暂停」开关；自动化浏览器里默认是暂停。

## Driving it with kui.mjs

前置：`$KUI doctor` 全 OK。流程从 `#/order-book` 开始，中途点目录换到 `#/depth-chart`、`#/trade-tape`。订单簿收到 `section.getByRole('group', { name: '订单簿（演示）' })`，行是 `[data-slot="book-row"]`，用 `data-side="ask" / "bid"` 分两侧。

- **默认两侧。** 打开页。`显示模式` 里「买卖」`aria-pressed="true"`，`合并档位` 里「0.01」按下；卖盘、买盘各 8 行，两侧从上往下价格递减，卖盘最后一行 `100.01`、买盘第一行 `100.00`；`[data-slot="book-spread-value"]` 写 `0.01`；卖盘列表的下沿不低于中间行的上沿，中间行的下沿不低于买盘的上沿。
- **占比条。** 把两侧 `[data-slot="book-size"]` 的量按整数千分之一加起来。`book-share-bid` 写 `买 X%`、`book-share-ask` 写 `Y% 卖`，X 与 Y 按「买量 /（买 + 卖）取到 0.1%，卖 = 100 − 买」算出来；`getByRole('img', { name: '买盘占 X%，卖盘占 Y%' })` 可见；买盘累计列逐行等于量的累加。
- **只看买。** `modes.getByRole('button', { name: '只看买', exact: true }).click()`。它 `aria-pressed="true"`；卖盘 0 行、买盘 16 行；占比条的字没变。
- **只看卖，再回买卖。** 点「只看卖」：买盘 0 行、卖盘 16 行；点「买卖」：回到 8 + 8。
- **合并到 0.5。** `ticks.getByRole('button', { name: '0.5', exact: true }).click()`。它按下；屏上每个价按分算都是 50 的倍数；卖盘最优 `100.50`（100.01 向上并进去），买盘最优 `100.00`；价差仍写 `0.01`。
- **点价。** 点买盘第一行：`[data-gallery-picked]` 写 `点价：100.00 · 买盘…`；点卖盘最后一行：写 `点价：100.50 · 卖盘…`。
- **深度图键盘。** 点目录 `a.k-sidenav-link[href="#/depth-chart"]`；`plot.focus()` 后按 `ArrowRight`：`[data-slot="depth-readout"]` 写 `卖盘 100.01 · 累计量 <订单簿默认时卖盘最后一行的累计> · 距中间价 0.00%`（舍入成零不带正负号，#187），`[data-slot="lcd-tooltip"]` 出现；按 `ArrowLeft`：读到 `买盘 100.00`；按 `Escape`：读数清空、读数框消失。
- **深度图鼠标。** `plot.hover({ position: { x: 宽 × 0.25, y: 高 / 2 } })`：读数写买盘、`距中间价 -N.NN%`；鼠标移到页标题上：读数清空。
- **成交明细逐笔。** 点目录 `#/trade-tape`。`[data-slot="tape-row"]` 18 行，没有 `×n`；`data-side` 里 `buy`、`sell` 都有，两侧 `.k-tape-price` 的计算颜色不同；时间从新到旧。
- **聚合。** `getByRole('group', { name: '聚合' }).getByRole('button', { name: '聚合', exact: true }).click()`。出现 `×n` 徽标，相邻两行不再是同价同向。
- **证据。** `$KUI drive orderbook`：十步十张截图，`order-book-default.aria.yml` 是默认时订单簿的 ARIA 快照；第七步的累计量与第一步记下的订单簿累计量是同一个数（深度图与订单簿吃同一份演示档位）。

## Gotchas

- 演示数据由固定种子的模拟器生成，自动化浏览器（`navigator.webdriver`）里默认暂停，首屏每次一样，所以流程里能写死 `100.01`、`100.00`、`100.50`。地址带 `?live=1` 或点了「实时」，数就会动，写死的值不再成立；要动一步用页上的 `window.__liveStep(n)`，那是调试入口，不算用户路径。
- 「合并档位」的按钮名是 `0.01`、`0.05`、`0.1`、`0.5`、`1`：找「0.5」「1」都要 `exact: true`，不然「1」会匹配到「0.1」「0.01」。
- 屏上的价与量带千分位（`1,234.567`），比数前去掉逗号再换成整数分 / 千分之一，不要直接比浮点。
- 深度图没有可点的档位元素，鼠标读数只能按图的相对位置放（宽度的几分之几），不要写页面的绝对坐标。精确对档用键盘。
- 订单簿只有给了 `onPriceSelect` 的行才是按钮；文档站的演示给了，接到别处时行可能点不动。
